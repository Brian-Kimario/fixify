# FIXIFY — PRODUCT CONTEXT & ARCHITECTURAL FOUNDATION

> **Core Product Rule**: Fixify is a property-maintenance platform, NOT a generic SaaS software startup or construction portfolio.
> **The Core Promise**: *Problem intake -> Right service -> Verified professional -> Transparent job -> Documented property record.*

---

## 1. Product Mission & Value Proposition
- **Turn Messy Problems into Clear Actions**: Customers rarely know the technical diagnosis (e.g. "water leaking under sink"). Fixify helps them describe it via text, photos, or voice, matches with verified pros, coordinates on-site inspection, provides line-item quotes before charges, and archives completed jobs into a persistent **Property Maintenance Record**.
- **Three Concrete Personas**:
  1. **Customer** (`/customer`): Requesting service, viewing quotes, tracking arrival, reviewing property asset records.
  2. **Professional** (`/professional`): Field workspace, today route, job requests queue, on-site inspection recording, quote submission, earnings.
  3. **Admin / Operations** (`/admin`): Resolving exceptions, pro document verification, dispute mediation, system signals.

## 2. Design System & Brand Identity Rules
- **Light-First Environment**: Primary canvas is warm Porcelain (`#F7F4EC`), raised surfaces are Paper (`#FFFEFA`), text is graphite Ink (`#18211F`), brand accent is Fixify Teal (`#176B5B` / `#0D5144`), with warm Clay (`#A9523D`) accents.
- **Strict Anti-Patterns**:
  - NO purple/blue generic AI gradients or "sparkles".
  - NO dark mode as default for customer surfaces (dark mode is reserved for pro field night use or selective operational panels).
  - NO fake metrics, fake countdown timers, or generic chatbot bubbles.
  - Sizing & clear space: Logo and marks must be restrained and purposeful.

## 3. Business & Operational Logic Rules
- **Pricing Transparency**: Jobs must NEVER be treated as fixed instant checkouts unless standard flat-rate. Most repairs follow: *Intake -> On-site Inspection -> Quote Draft -> Customer Explicit Approval -> Work -> Completion Evidence -> Payment*.
- **PostgreSQL State Machine**: Transitions are enforced at the database level via `transition_job_state()`. UI must reflect authoritative state machine stages without skipping steps.
- **Persistent Property Record**: Finished jobs link to properties and property assets (e.g. "Boiler serial #123"), creating long-term home maintenance equity.
