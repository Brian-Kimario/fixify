ENVIRONMENT VARIABLES:
  Before:  NEXT_PUBLIC_STRIPE_PUBLIC_KEY
           STRIPE_SECRET_KEY
           STRIPE_WEBHOOK_SECRET

  After:   NEXT_PUBLIC_RAZORPAY_KEY_ID
           RAZORPAY_KEY_SECRET
           RAZORPAY_WEBHOOK_SECRET

PAYMENT ADAPTER PATH:
  Before:  src/lib/payments/stripe.ts (or square.ts)
  After:   src/lib/payments/razorpay.ts

PAYMENT API ROUTES:
  Before:  /api/webhooks/payment
  After:   /api/webhooks/razorpay
           /api/payments/razorpay/create-order
           /api/payments/razorpay/verify

AMOUNT HANDLING:
  Before:  Handled in minor units (cents for USD)
  After:   Paise (100 paise = 1 INR)
           Always convert: rupees × 100 → paise
           Always convert back: paise ÷ 100 → rupees

CURRENCY:
  Before:  USD or other currencies
  After:   INR (₹) only

SIGNATURE VERIFICATION:
  Before:  Provider-specific signature format
  After:   HMAC-SHA256(orderId|paymentId, webhook_secret)

API ENDPOINTS:
  Before:  Stripe: https://api.stripe.com/...
  After:   Razorpay: https://api.razorpay.com/v1/...

WEBHOOK EVENTS:
  Before:  charge.succeeded, charge.failed, etc.
  After:   payment.authorized, payment.captured, payment.failed

 IMPORTANT NOTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. PAISE CONVERSION (Critical!)
   Razorpay uses paise, not rupees:
   
   ✓ Correct: amountInRupees × 100 = amountInPaise
   ✗ Wrong: Sending rupees directly to Razorpay
   
   Example:
   Customer pays ₹100
   Store in DB: 100.00 (rupees)
   Send to Razorpay: 10000 (paise)
   Store in payments: amount: 100.00, currency: 'INR'

2. SIGNATURE VERIFICATION (Critical!)
   Must verify every payment:
   
   Client response signature:    orderId|paymentId
   Webhook signature:            Raw request body (JSON)
   Always use: HMAC-SHA256 with RAZORPAY_WEBHOOK_SECRET

3. IDEMPOTENCY (Important!)
   Webhooks may fire twice:
   
   ✓ Correct: Check if payment_id already in DB
   ✗ Wrong: Create duplicate payment records
   
   Query: SELECT * FROM payments WHERE provider_payment_id = $1

4. NO CLIENT-SIDE TRUST (Security!)
   Never trust amount from browser:
   
   ✓ Correct: amount = SELECT amount FROM bookings WHERE id = $1
   ✗ Wrong: amount = req.body.amount

5. AMOUNT DISPLAY
   Always show in ₹ (rupees) to user:
   
   Display: ₹500
   Send to Razorpay: 50000 paise
   Store in DB: 500.00

 WHY RAZORPAY OVER STRIPE/SQUARE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Razorpay:
  ✓ India-based, built for Indian market
  ✓ Native INR support
  ✓ ~2% fees (lowest in India)
  ✓ Supports UPI (most popular in India)
  ✓ Simple modal integration
  ✓ Excellent Indian customer support
  ✓ Sandbox available for testing

Stripe:
  ✗ International focus, India is secondary
  ✗ INR support via 3rd party
  ✗ 2.9% + 30 INR fees (higher)
  ✗ No native UPI support
  ✗ More complex integration
  ✗ US-based support (timezone issues)

Square:
  ✗ Limited in India
  ✗ Not primary focus
  ✗ Fewer payment methods
  ✗ Limited local support

DECISION: Razorpay is perfect for India. No regrets.
